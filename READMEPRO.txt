# HARDWARE MANAGEMENT SYSTEM

### Complete Hardware Store, Inventory, Point of Sale & Business Management Solution

**Manage Stock. Process Sales. Control Purchases. Track Finances. Grow Your Business.**

A modern, integrated business management platform designed to help hardware stores, building-material suppliers, wholesalers, distributors, and construction-material businesses manage their daily operations efficiently from one centralised system.

The Hardware Management System brings together inventory management, point of sale (POS), procurement, supplier management, customer accounts, credit sales, financial operations, reporting, and business intelligence into one unified application.

It is designed to reduce manual work, improve stock accuracy, strengthen financial accountability, streamline business operations, and give business owners better visibility into their businesses.

---

## Project Overview

Hardware businesses manage complex operations involving thousands of products, different units of measurement, multiple suppliers, changing purchase prices, retail and wholesale sales, customer credit, stock movements, and daily financial transactions.

Managing these activities using spreadsheets, notebooks, and disconnected applications can lead to stock inaccuracies, financial inconsistencies, delayed reporting, and unnecessary operational costs.

The Hardware Management System addresses these challenges through a centralised digital platform that connects the major activities of a hardware business.

From purchasing building materials to receiving stock, processing customer orders, collecting payments, issuing receipts, and monitoring business performance, the platform is designed to provide a structured and accountable operational environment.

**This is more than an inventory application. It is a complete operational management solution for modern hardware businesses.**

## The Business Problem We Solve

Hardware businesses commonly face challenges such as:

- Difficulty tracking large product inventories.
- Inaccurate stock quantities.
- Poor visibility into product costs and selling prices.
- Manual sales and receipt preparation.
- Slow customer checkout processes.
- Difficulty managing wholesale and retail prices.
- Untracked customer credit sales.
- Poor supplier payment visibility.
- Inconsistent purchase records.
- Difficulty managing different product units and packaging.
- Limited visibility into business profitability.
- Inadequate sales and inventory reports.
- Limited accountability across employees and cashiers.
- Difficulty managing multiple warehouses or branches.

The system provides a unified approach to these operational challenges through connected workflows, centralised records, controlled access, and meaningful business reporting.

## Installation & Local Development

### Prerequisites

Install or configure:

- Node.js (compatible with the project's dependencies).
- npm.
- XAMPP.
- MySQL/MariaDB service through XAMPP.
- Git.
- A code editor such as Visual Studio Code.

### 1. Clone the Repository

Replace the example repository URL with the actual published GitHub repository URL.

```bash
git clone YOUR_GITHUB_REPOSITORY_URL
```

Navigate into the project:

```bash
cd hardware-management-system
```

### 2. Install Dependencies

Follow the actual package structure.

For a root-managed project:

```bash
npm install
```

For separate frontend and backend packages:

```bash
cd frontend
npm install

cd ../backend
npm install
```

### 3. Configure XAMPP

1. Open XAMPP Control Panel.
2. Start Apache if required by the local setup.
3. Start MySQL.
4. Open phpMyAdmin.
5. Create the required application database.
6. Configure the database connection in the backend environment file.

Use the actual database name, username, password, host, and port configured on your machine.

### 4. Configure Environment Variables

Create the appropriate `.env` file based on `.env.example`.

Example configuration:

```env
NODE_ENV=development

PORT=5000

DATABASE_URL="mysql://root:@localhost:3306/hardware_management"

JWT_SECRET="replace-with-a-secure-random-secret"

FRONTEND_URL="http://localhost:5173"
```

The database URL is illustrative. Use the exact format required by the database driver or ORM in the actual project.

Never commit real secrets to GitHub.

### 5. Run Database Migrations

Execute the migration command configured by the project.

For example:

```bash
npm run db:migrate
```

Seed development data if required:

```bash
npm run db:seed
```

### 6. Start the Application

Use the scripts defined in the actual `package.json`.

A typical separate frontend/backend setup may use:

```bash
npm run dev
```

Or start each service independently using the project's configured development scripts.

### 7. Open the Application

Use the local frontend URL displayed in the development server terminal, commonly:

```text
http://localhost:5173
```

The backend API should run on its configured local port.

**Installation note:** Commands and environment variables must match the actual repository configuration. The examples above are starting points, not a claim that every script or configuration has already been implemented.

### PostgreSQL Migration Strategy

The application is designed with future PostgreSQL migration in mind.

A proper migration process should include:

1. Back up the existing MySQL/MariaDB database.
2. Create the PostgreSQL database.
3. Apply PostgreSQL-compatible migrations.
4. Map and transfer existing records.
5. Validate relationships and constraints.
6. Verify decimal and financial values.
7. Test authentication and permissions.
8. Test inventory operations.
9. Test POS and financial workflows.
10. Reconcile record counts and important totals.
11. Perform full application testing before production cutover.

Never migrate a live production database without a verified backup and recovery plan.
