## 1.4 Database Architecture — XAMPP Now, PostgreSQL Anytime

XAMPP is already installed on my computer.

The system must work reliably with the available XAMPP MySQL/MariaDB database service for local development.

At the same time, the complete application must be architecturally prepared for PostgreSQL migration.

Requirements:

- Centralized database configuration.
- Environment-based database selection.
- Proper ORM, query builder, or database abstraction.
- Database migrations.
- Database seeders.
- Foreign key constraints.
- Appropriate database indexes.
- Referential integrity.
- Transaction management.
- Accurate financial data types.
- Database-independent business logic.

Support:

1. XAMPP MySQL/MariaDB for local development.
2. PostgreSQL for future production deployment.

Do not confuse XAMPP's MySQL/MariaDB service with PostgreSQL.

Avoid database-specific SQL scattered throughout the application.

Pay special attention to compatibility involving:

- Auto-incrementing IDs.
- Boolean values.
- Date and timestamp handling.
- Decimal precision.
- JSON fields.
- ENUM dependencies.
- Reserved SQL keywords.
- Foreign keys.
- Transaction behavior.
- Indexing.
- Database migrations.

Use precise decimal types for financial calculations.

Do not use floating-point arithmetic for monetary values.

**Important:** Do not claim PostgreSQL compatibility merely because a PostgreSQL connection setting exists. Validate the schema, queries, migrations, and critical business workflows against PostgreSQL before declaring compatibility.
